# ADR 0001: プレビューの図をクリックして、ソースのその部品へ飛ぶ

- 状態: 起草(2026-11-21)
- 関連: core の ADR 0072(D6 の位置の地図 `build --locations`、D1 の位置の形)、この拡張の Phase 2

## 背景

プレビュー(`src/preview.ts`)は `build <src> --out <scratch>/<name>.svg --no-lint` で描いた SVG を、webview に `innerHTML` で入れるだけ。図のどこがソースのどこかは分からない。
core 0.9.0 から `build --locations FILE` が、部品と接続ごとに SVG の `viewBox` の座標の四角と、ソースの位置を JSON で書く(ADR 0072 D6)。この ADR は、その地図をプレビューでどう使うかを決める。

地図の形(core の `lib/locations-map.ts`。0.9.0 の tarball で確かめた):

- 上: `version: 1`、`source`、`provenance`、`width`、`height`、`diagram: {loc}`、`parts[]`、`connects[]`、落ちたときだけ `issues[]`。
- `parts[i]`: `{loc: {file, line, column}, via?: [{line, column}], kind, label, rect: {x, y, w, h}, node?, reveal?, until?, final?: false, generated?: true}`。
- `connects[i]`: 同じ位置と `rect` に、`segments: [x1, y1, x2, y2][]`。
- `loc.file` は**地図のあるディレクトリから**の相対パス。プレビューの地図は拡張の作業用フォルダにあるので、`../../…/src/flow.ts` の形になる。

## 決定

**D1. 地図は、使える core のときだけ作る。** `buildArgs` に `--locations <scratch>/<name>.locations.json` を足すのは、CLI の版(`ResolvedCli.version`。`package.json` から読む)が 0.9.0 以上のときだけ。
版が分からない、または古いときは足さない(今のとおり描くだけで、クリックは効かない)。未知のオプションで `build` を落とさないため、試しに渡して落ちたら外す、ということはしない。

**D2. 地図は SVG と一緒にページへ送る。** `ToPage` の `svg` に `map?: PreviewMap` を足す。拡張は、読んだ地図から次だけを残して送る(ページに要らない物とパスを渡さない):

- 部品と接続ごとに `{id, kind, label, rect, segments?}`。`id` は送った並びの番号。
- `final: false`(最後の図に出ない)部品は落とす。プレビューは最後の図を描くので、押しても見えない物に当たらない。
- 位置(`loc`・`via`)は拡張の側に残し、`id` で引く。ページはファイルのパスを知らない。
- 地図が読めない、`version` が 1 でない、`width`/`height` が SVG と合わないときは、`map` を送らない(クリックは効かない。誤った所へ飛ぶより良い)。

**D3. ページは、クリックの点を SVG の座標に直して引く。** `svg.getScreenCTM().inverse()` で点を `viewBox` の座標に直す(幅に合わせる・拡大でも合う)。当たりの決め方(core の ADR 0072 D6 に合わせる):

- 部品: 点が `rect` の中。接続: 点から `segments` のどれかまでの距離が、画面で 6px 以内(座標の倍率で割る)。接続の見出しは `rect` の中。
- いくつも当たれば、接続を先に、次に `rect` の面積の小さい方、同じなら後の物。`group` の中の箱は面積で先に当たる。
- 当たりの計算は、ページの外に置ける純粋な関数(`hitTest(map, point, scale)`)にし、単体テストする。ページへは文字列として埋める。

**D4. 操作。**

- 当たる物の上では、その四角を細い枠で示し(`pointer-events: none` の重ねた SVG)、`title` に `label` と `kind` を出す。カーソルは `pointer`。
- **クリック**でソースへ飛ぶ。ページは `{kind: 'reveal', id}` を送り、拡張が `loc` を開く。
  - 開く所: そのファイルがすでに開いているエディタの列。無ければ、プレビューでない最初の列(`ViewColumn.One`)。プレビューの列には開かない。
  - 選ぶ範囲: `loc` の行・桁から、識別子の終わりまで(波線の置き方 `placeFinding` と同じ)。エディタをそこまでスクロールする。
  - `loc.file` は、地図のディレクトリから絶対パスにする。ファイルが無いときは何もしない(ログに 1 行)。
- 何も当たらないクリックは何もしない(図を選ぶ・ドラッグして文字を選ぶ、を邪魔しない)。ドラッグ(押してから 4px 以上動いた)はクリックにしない。

**D5. 地図は保存したソースの位置。** プレビューは保存のたびに描き直すので、地図は最後に保存したソースのもの。

- 描いたときのソースの文書の `version` を覚える。クリックのときに文書が保存されていない変更を持つ(`isDirty`)か `version` が違うなら、飛んだうえで、ステータスバーのメッセージ(数秒)で「保存前の位置です」と言う。行を推測でずらさない。
- 別のファイル(共通の部品)の位置は、そのファイルの状態を見ない(依存の保存でも描き直すので、ほぼ合う)。

**D6. 描けなかったときの帯も、位置へ飛べるようにする。** 検査に落ちると SVG は無いが、地図は `issues` を持って書かれる(ADR 0072 D6)。
地図に `issues` があれば、帯の各行を `issues` から作り、位置のある行を押すとその位置へ飛ぶ(D4 と同じ開き方)。地図が無いときは今の `buildErrorText`。

**D7. ソースから図へ(後でよい)。** エディタのカーソルの行が、部品の `loc`(か `via`)の行と同じなら、その部品の枠をプレビューで光らせる。U3 にし、U1・U2 を使ってみてから決める。

**D8. 安全。** 地図は拡張が作業用フォルダに書かせた物だけを読む。ページへ送るのは番号・種類・見出し・座標だけで、見出しは `textContent` で入れる。ページから来る `reveal` は `id` だけで、拡張は自分の持つ表で引く(ページがパスやコマンドを指定できない)。CSP は変えない。

## やらないこと

- SVG に位置を書く(core の ADR 0072 D6 で退けた。ドリフトの検査が落ちる)。
- `reveal` の途中の段のプレビュー。部品の中の項目(`cycle` の各点など)まで絞ること(core の位置は部品の呼び出しまで)。
- 保存していない変更を描く(プレビューは保存で描く)。

## 実装の順

- **U1**: D1〜D5、D8。`buildArgs` と版の判定、地図の読み込みと絞り込み(純粋)、`hitTest`(純粋)、ページの枠とクリック、`reveal` の受け取りと開き方。単体テスト: 版で `--locations` の有無、絞り込み(`final: false` を落とす、合わない地図を捨てる、パスを渡さない)、`hitTest`(重なり・接続の距離・倍率)、位置の絶対パス。結合テスト: 0.9.0 の core で、例の図を描き、地図を受け、`reveal` でその行が選ばれる。古い core(0.8.0)では `--locations` を渡さず、今の結合テストが通る。
- **U2**: D6(帯の行から飛ぶ)。
- **U3**: D7(ソースから図へ)。U1・U2 のあとで決める。

## 結果

- 図の部品を押すと、それを書いた行へ飛ぶ。共通の部品の中の物は、その部品のファイルへ。
- 古い core では、今と同じ(描くだけ)。
- 結合テストの core を 0.9.0 に上げる必要がある(npm に 0.9.0 が出てから)。

## Open questions

1. D1: 版が分からない CLI(`cliPath` で package.json の無い所を指すとき)でも試しに `--locations` を渡すか。今は渡さない。
2. D4: 普通のクリックで飛ぶか、Ctrl/Cmd+クリックにするか。今の案は普通のクリック(プレビューに他のクリックの操作が無い)。
